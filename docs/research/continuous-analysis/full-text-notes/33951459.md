## What the method does (abstract + docs + code; NOT the paper's full text)
- Model / statistic: build a KNN graph of cells from any metric: a latent space (e.g. PCA or other embedding), spatial coordinates, a lineage tree (ete3), or a precomputed distance matrix (docs, "Choosing different metrics"). For each gene, standardize counts against a null model fitted per cell assuming no correlation between cells: "danb" (depth-adjusted NB from M3Drop), "bernoulli" (detection only), "normal" (scaled by UMI count) or "none" (pre-standardized). The local autocorrelation is the sum over graph edges of w_ij x_i x_j (code: local_cov_weights); its mean and variance under the null are computed analytically (compute_moments_weights) to give a Z-score, P value and BH FDR; C is a -1..1 scaled coefficient (docs table).
- Modules: pairwise "local correlations" between informative genes (Z-scores), agglomerative clustering with an FDR stop and a minimum module size; per-cell module scores (docs).
- Null / calibration: analytic Z from the per-cell null model; cells are treated as independent observations, so there is no replicate level and spatial or graph structure within one sample is the only signal tested.
- Replicates: none.
- Validation (abstract only): T helper cells (nuanced transcriptional variability), spatial patterns in the cerebellum (Slide-seq per the docs' example data), lineage-tree data. No numbers available to us.
- Plots (docs): local-correlation heatmap with module bars (plot_local_correlations); module scores on spatial coordinates or embeddings.
- Software: Python package "hotspotsc" (pip), https://github.com/YosefLab/Hotspot.

## Fit to our design (2-4 lines, revised from docs/code only)
A count-aware way to find gene modules that co-vary over neighbouring units, including physical neighbourhoods in the section, which could expose programs not tied to the PT coordinate. For positional programs it adds little over our curve clustering, and its tests are unit-level. Paper-level claims remain unverified.
