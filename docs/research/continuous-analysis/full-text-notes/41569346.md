## What the paper actually does (from the full text)
- Model / statistic: four R functions. getClusters: sum-of-squared-errors elbow to choose the cluster number (user decides). clusterData: k-means or fuzzy c-means (Mfuzz-style) on a normalized expression matrix, or import of WGCNA modules, Seurat markers, or Monocle2/3 pseudotime output. enrichCluster: per-cluster GO/KEGG/custom over-representation through clusterProfiler (enrichGO/enrichKEGG/enricher) or enrichR, with a user P-value cutoff. visCluster: composite ComplexHeatmap/ggplot2 figure (Implementation).
- Null / significance: only the ORA p-values of clusterProfiler; no test of temporal pattern, no cluster stability assessment.
- Replicates: none modelled; input is a matrix of samples/time points or cell-type/pseudotime-binned averages.
- Validation: demonstrations only - mouse pre-implantation proteome (Fig. 2-3), PBMC 3k markers (Figs 4, 6), Monocle2 HSMM myoblast pseudotime branches (Fig. 5). No benchmark.
- Plot types: the composite panel - per-cluster line plots of member trends (left), z-score heatmap (centre), GO/KEGG term annotations and bar plots (right) (Fig. 2); WGCNA module line plots + heatmap (Fig. 3); branch-wise pseudotime heatmap (Fig. 5); custom inserted plots such as UMAP or bar plots per cluster (Fig. 6); Shiny app (Fig. 7).
- Software: R package (GitHub junjunlab/ClusterGVis; Bioconductor per abstract and File S1; the code-availability section says CRAN); Shiny app on shinyapps.io.
- Limitations stated: none.
- Limitations for OUR design: purely descriptive; hard cluster calls by k-means with an SSE elbow; enrichment discards position inside a cluster; no specimen-level replication.
